# Firebase backend setup (wiccan-android)

Brings the real `wiccan-android` Firebase project up to the point where the
app can be built, signed, and pushed to a Play Store testing track.

Steps marked **CONSOLE** need a browser session signed in as the project
owner — they cannot be done from the repo. Steps marked **REPO** are
already done and are recorded here so the state is auditable.

## 0. Blocker: Google Sign-In is not configured

**This blocks compilation, not just sign-in.**
`AuthRepositoryImpl.signInWithGoogle` reads
`R.string.default_web_client_id`. That string resource does not exist in
the repo — it is generated by the Google Services Gradle plugin from the
`oauth_client` array in `app/google-services.json`.

The current `google-services.json` has `"oauth_client": []`, so the plugin
generates no such string. Verified by inspecting the plugin's own output,
`app/build/generated/res/processProdDebugGoogleServices/values/values.xml`,
which contains `google_api_key`, `google_app_id`, `project_id`,
`gcm_defaultSenderId` and `google_storage_bucket` — and no
`default_web_client_id`.

CI does not catch this: `app/google-services.ci.json` carries a dummy
`oauth_client` entry with `client_type: 3`, so the resource exists on the
CI classpath and the real config's gap stays invisible until someone
builds with the real file.

**CONSOLE — fix:**

1. Firebase Console → Authentication → Sign-in method → enable **Google**.
   Enabling it provisions the OAuth web client automatically.
2. Also enable **Email/Password** — `signInWithEmail` is wired to the same
   sign-in screen and fails the same way without it.
3. Project settings → Your apps → Android → **re-download
   `google-services.json`** and replace `app/google-services.json`.
4. Confirm the re-downloaded file has a non-empty `oauth_client` array with
   a `"client_type": 3` entry.

Verify the fix without launching the app:

```bash
# run from the repo root
./gradlew :app:processProdDebugGoogleServices
grep default_web_client_id \
  app/build/generated/res/processProdDebugGoogleServices/values/values.xml
```

A match means the app will compile. No match means step 3 did not take.

## 1. Billing plan

**CONSOLE.** Cloud Functions will not deploy on the free Spark plan.
Firebase Console → upgrade `wiccan-android` to **Blaze**. Set a budget
alert at the same time — the scheduled jobs
(`sendDailyNotificationsJob` hourly, `recheckLapsedSubscriptionsJob`
daily) run whether or not anyone uses the app.

## 2. Firestore

**CONSOLE.** Firebase Console → Firestore Database → Create database.
Pick the region deliberately: it is permanent, and Cloud Functions default
to `us-central1`, so `nam5`/`us-central` avoids a cross-region hop on every
call.

**REPO.** Rules and indexes are written and ready to deploy:

```bash
firebase deploy --only firestore:rules,firestore:indexes --project production
```

## 3. Authentication

**CONSOLE.** Covered by step 0 — Google and Email/Password enabled.

`onUserCreated` is a **v1 Auth trigger** (`authV1.user().onCreate`). It
fires on user creation and seeds the user profile document; no extra
console setup, but note it is the one function in `index.ts` still on the
v1 API, so it deploys as a 1st-gen function.

## 4. App Check

**CONSOLE.** Every callable function in `index.ts` is declared
`onCall({ enforceAppCheck: true })` — all eight of them reject unattested
calls outright. Until App Check is registered, a real build gets
`UNAUTHENTICATED` on every single backend call.

1. Firebase Console → App Check → register the Android app with
   **Play Integrity**.
2. For local debug builds, the app installs the debug provider via
   `app/src/debug/.../DebugAppCheckModule.kt`. Run the debug build once,
   copy the debug token it logs, and paste it into App Check → Manage
   debug tokens. This is per-install and must be repeated on each device.

## 5. Cloud Functions secrets

**CONSOLE + LOCAL.** Create `functions/.env.wiccan-android` (gitignored —
never commit it; `functions/.env.example` is the template):

- `ANTHROPIC_API_KEY` — required by `generateDraft` / `npm run generate-draft`.
- `GOOGLE_APPLICATION_CREDENTIALS` — path to a service account JSON with
  Google Play Developer API access. Required by `verifyPurchase`,
  `recheckLapsedSubscriptionsJob`, and `handlePlayRtdn`.
- `ANDROID_PACKAGE_NAME` — optional. Defaults to `com.jaimesorrow.wiccan`,
  which matches the current applicationId, so leave it unset unless that
  changes.

## 6. Play RTDN (Pub/Sub)

**CONSOLE.** `handlePlayRtdn` subscribes to the topic named by
`PLAY_RTDN_TOPIC`, default `play-rtdn`.

1. Create a Pub/Sub topic named `play-rtdn` in the `wiccan-android` GCP
   project.
2. Play Console → Monetization setup → Real-time developer notifications →
   point it at that topic's full path
   (`projects/wiccan-android/topics/play-rtdn`).
3. Grant Google Play's service account publish rights on the topic.

## 7. Deploy

```bash
cd functions && npm install && npm run build && npm test
cd .. && firebase deploy --project production
```

`production` must be named explicitly. `.firebaserc`'s `default` and
`staging` aliases are still unresolved placeholders, so a bare
`firebase deploy` fails rather than silently shipping to production.

## Local testing with the emulator suite

The full backend runs locally with no Blaze plan, no credentials, and no
risk to production data. Configured in `firebase.json`.

```bash
cd functions && npm install && npm run build
cd .. && firebase emulators:start --project wiccan-android
```

Emulator UI at <http://127.0.0.1:4000>. Ports: auth 9099, functions 5001,
firestore 8080, pubsub 8085.

All twelve functions initialize. Rebuild (`npm run build`) after editing
anything under `functions/src` — the emulator serves compiled output from
`functions/lib`.

### End-to-end script

`scripts/e2e-emulator.mjs` drives the whole backend against the emulators:
it seeds content, creates a real Auth user, and exercises the paths unit
tests cannot reach.

```bash
# terminal 1
cd functions && npm install && npm run build
cd .. && firebase emulators:start --project wiccan-android
# terminal 2
node scripts/e2e-emulator.mjs
```

### App Check blocks this script by default

All 8 callables are `enforceAppCheck: true`, the Functions emulator
honors that, and there is no App Check emulator to mint a token — so every
callable returns `UNAUTHENTICATED` even with a valid ID token. The
emulator log shows the split precisely:

```
{"verifications":{"app":"MISSING","auth":"VALID"}}
```

The script detects this case and explains it rather than reporting a wall
of bogus failures. Two ways forward, neither yet adopted:

- Scope enforcement to non-emulator runs —
  `enforceAppCheck: process.env.FUNCTIONS_EMULATOR !== "true"`. The
  Functions emulator sets `FUNCTIONS_EMULATOR=true` and deployed functions
  never do, so production enforcement is unchanged. This is a deliberate
  weakening of an audit-hardened control in one environment, so it needs
  an explicit decision rather than a quiet default.
- Drive the flows from a real debug build with an App Check debug token
  registered (§4), which tests the real client path but cannot run in CI.

With enforcement isolated locally, the suite passes 18/18, covering:
authenticated and unauthenticated `getTodayContent`; daily-assignment
stability across repeat calls (same content returned twice); tier gating
(a free user is never served premium or draft content); the
`userContentHistory` write; `acceptTerms` and the `users/{uid}` document;
`registerDeviceToken` and the `users/{uid}/devices` subcollection; the
`devices` collection-group query; `verifyPurchase` argument validation;
the `dailyContentEnabled` kill switch; and the `deleteUserData` cascade.

That covers three things `docs/STATUS.md` previously listed as never
exercised against a real Firestore: the collection-group device query, the
daily-assignment transaction, and the deletion cascade.

## Still blocked after all of the above

- `PolicyUrls` (`app/src/main/kotlin/com/wiccan/app/core/config/PolicyUrls.kt`)
  still points at unhosted `wiccan.app` URLs. Play rejects listings with
  placeholder legal URLs, and the Data Safety form requires a publicly
  reachable account-deletion page. Needs a real domain and three hosted
  pages.
- No release keystore exists — see `docs/RELEASE_CHECKLIST.md`.
- `dev` and `staging` flavors still have no Firebase project of their own.
